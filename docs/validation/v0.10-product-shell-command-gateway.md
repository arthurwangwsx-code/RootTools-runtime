# v0.10 Product Shell & Command Gateway Validation

## Scope

This checkpoint starts the product/runtime convergence without changing the privileged execution model.

Implemented:

- five-tab `Overview / Device / Tasks / Agents / Settings` product shell;
- system appearance instead of forced dark mode;
- existing management screens reorganized by user intent;
- Tasks surface for lock-aware state, recent jobs, controlled actions and audit;
- Agents surface separating current trusted callers from planned AiBox/network integrations;
- canonical `POST /v1/commands/submit` ingress;
- `/v1/action` retained as compatibility ingress;
- `commandGateway=true` hello feature negotiation;
- RootTools App uses the canonical command ingress for typed actions.

## Compatibility

- Existing clients using `/v1/action` remain supported.
- Capability IDs, risk policy, provider routing, receipts, revision and idempotency semantics are unchanged.
- The new Command Gateway is an ingress seam, not a new executor.

## Not yet claimed

- principal IDs/grants beyond the current owner/agent credentials;
- same-device AiBox pairing;
- network Skill relay;
- new semantic UI actions;
- physical-device v0.10 deployment/visual acceptance.

Those are subsequent P9/P10 increments and must build on the same command/capability lifecycle rather than adding transport-specific privileged paths.
