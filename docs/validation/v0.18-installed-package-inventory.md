# v0.18 Installed Package Inventory Validation

## Scope

v0.18 adds device-wide **read-only** installed-package observation without widening package mutation authority.

The daemon parses the rootless Procursus `dpkg` status database and exposes only records whose Debian status is exactly `install ok installed` through:

- `GET /v1/packages/installed`;
- `DaemonClient.installedPackageCatalog()`;
- Device > Packages > Installed on device;
- Mac Device Service command `package-installed`.

## Contract

Each installed package projects:

- package ID;
- version;
- architecture;
- source `procursus-dpkg`;
- status `installed`;
- section and priority;
- first-line description;
- installed size in KiB;
- `Essential` flag.

The parser has a test-only `ROOTTOOLS_DPKG_STATUS` override so unit and HTTP acceptance use deterministic fixtures rather than the host Mac package database.

## Product acceptance

- Packages keeps RootTools-managed staging/lifecycle controls separate from device-wide installed inventory.
- Installed packages support search by package ID, description, section, or version.
- The UI can filter to essential packages and presents source/status explicitly.
- Failure of the new installed-inventory endpoint does not erase the existing staged package surface.
- Installed inventory rows intentionally expose no uninstall/rollback action.

## Security invariant

Reading all installed packages does **not** authorize arbitrary package mutation.

`device.package.uninstall-deb`, `device.package.uninstall-ipa`, and rollback operations still require an existing RootTools-managed package record and retain their R2 Owner confirmation boundary. No caller-supplied package-manager argv, executable path, or raw shell is introduced.

## Automated acceptance

- `package_controller_test` verifies installed-only filtering, metadata projection, source/status, size, and essential-package parsing.
- HTTP contract verifies `/v1/packages/installed` against an injected `dpkg` fixture.
- full RootTools C/HTTP contract suite must pass from the exact staged snapshot;
- iOS 16 Release and rootless DEB packaging must pass from the exact staged snapshot before the milestone is considered stable.

## Physical-device boundary

At implementation time the reference iPhone still runs RootTools daemon v0.9.0. v0.18 installed-package inventory is not physically claimed until the trusted updater migration succeeds and `/v1/status` reports v0.18.0 (or a later consolidated stable daemon) on-device.
