# v0.20 Scoped Files Manager Validation

## Product invariant

Files Manager is a human-friendly projection of declared RootTools filesystem scopes, not a general root explorer.

The only roots remain the daemon-owned `mobile` and `bootstrap` scopes. A caller supplies only a bounded relative path within one of those roots.

## Safety acceptance

- absolute paths are rejected;
- empty, `.` and `..` traversal segments are rejected;
- relative paths are bounded to 512 bytes, eight segments and 96 bytes per segment;
- hidden/unsupported segments remain outside the product surface;
- intermediate directories are traversed with `openat(..., O_DIRECTORY | O_NOFOLLOW)`;
- directory listing uses `fstatat(..., AT_SYMLINK_NOFOLLOW)`;
- final reads/writes use `openat(..., O_NOFOLLOW)`;
- symlinks can be listed as facts but cannot be entered or read;
- reads remain bounded to 32 KiB and regular files;
- writes remain bounded to 16 KiB with `fsync` and descriptor-relative read-back verification;
- legacy root-level `name` requests remain compatible while new clients use `path`.

## Product surface

The iOS Files page provides:

- scope selector;
- declared physical root visibility;
- nested directory navigation and up-level navigation;
- per-directory search;
- file/directory/symlink type;
- size, POSIX mode and modification time;
- bounded text viewer/editor;
- new empty text-file creation;
- visible read/write limits and no-follow policy.

The Mac Device Service client accepts nested relative paths for `fs-list`, `file-read` and `file-write`.

## Automated acceptance

The HTTP contract creates a nested scope fixture and proves:

- root and nested directory listing;
- nested file read;
- nested file creation/write;
- parent traversal denial;
- symlink read denial;
- symlink directory-navigation denial.

The complete RootTools contract suite and iOS 16 Release build pass with the Files Manager enabled.

## Physical-device boundary

The reference iPhone still runs daemon v0.9.0. v0.20 Files Manager is source/build validated only until the trusted updater migration deploys the consolidated current daemon to the device.
