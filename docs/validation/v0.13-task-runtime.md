# v0.13 Task Runtime Validation

## Automated acceptance

- Contract tests pass with the legacy automation queue still readable.
- A locked-device fixture transitions an app-launch task to `waiting_for_unlock`.
- `/v1/tasks/catalog` reports task ID, capability, authenticated caller, `requiresUI`, attempts and lifecycle state.
- Canonical task cancellation transitions queued/waiting work to `cancelled`.
- `durableTasks=true` is advertised by `/v1/hello`.
- Device Task capabilities are bound to the RootTools control provider, not directly to the UI provider; the provider is selected only when the task executes.

## Release acceptance

- Full C/HTTP contract suite passes under `-Wall -Wextra -Werror`.
- iOS 16 arm64 daemon/updater build passes.
- iOS 16 Release SwiftUI build passes with the Tasks tab using `/v1/tasks/catalog`.

## Compatibility

The old automation API remains available as a projection during migration. New RootTools UI and host CLI paths submit/cancel canonical tasks.
