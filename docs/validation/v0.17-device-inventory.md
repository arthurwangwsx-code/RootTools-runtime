# v0.17 Device Inventory & Process Metrics Validation

## Application inventory

`device.app.list` and `device.app.inspect` now expose structured product metadata:

- bundle identifier;
- display name and executable;
- short version and build version;
- source (`system`, `jailbreak`, `user`);
- bundle path;
- running and critical flags.

HTTP contract uses injectable app roots and dynamically creates a fixture `.app/Info.plist`, proving catalog and inspect parsing without relying on the developer Mac's installed applications.

## Process metrics

`device.process.inspect` retains PID/UID/critical/privileged identity and adds a best-effort metrics snapshot using the Darwin `proc_pid_rusage` symbol:

- user/system CPU nanoseconds;
- resident bytes and physical footprint;
- disk bytes read/written;
- page-ins;
- package-idle and interrupt wakeups.

`metricsAvailable=false` is an explicit supported result when the OS refuses metrics for a process; identity inspection remains available.

## Product acceptance

- Device > Applications is a searchable structured list with version/source/running state and a detail page for launch/terminate.
- Device > Processes is a searchable PID/UID list with a resource detail page and R2 terminate action for non-root/non-critical processes.
- no raw process command line execution is introduced.

## Automated acceptance

- dynamic fixture app metadata contract passes;
- process inspect contract verifies the complete metrics schema;
- full RootTools C/HTTP contract suite passes under strict warnings;
- iOS 16 Release build is required before the milestone is committed.

## Physical-device boundary

The reference iPhone still runs v0.9.0; no v0.17 physical process metric values are claimed before trusted deployment.
