# v0.14 Semantic UI Automation Validation

## Contract acceptance

- `device.ui.observe` is a registered R0 capability bound to the UI provider.
- `device.ui.tap`, `device.ui.type`, and `device.ui.swipe` are registered R1 semantic capabilities whose command acceptance is owned by the Task Runtime.
- Invalid coordinates are rejected before task persistence.
- Locked-device contract fixtures persist tap/type/swipe as `waiting_for_unlock` tasks.
- Canonical task cancellation works for each queued UI task.
- The HTTP contract does not require ZXTouch to be installed on the test Mac; `device.ui.observe` fails cleanly with provider unavailable.
- `/v1/hello` advertises `semanticUIAutomation=true`.

## Execution safety

- Task execution re-checks global policy and Named Principal grant immediately before input.
- UI readiness is mandatory; lock/passcode bypass is not implemented.
- Touch coordinates are checked against fresh ZXTouch screen geometry.
- Tap and swipe keep their complete touch sequence on one socket.
- Text is bounded, UTF-8 validated, control characters are rejected, and each character uses the fixed insert-text subtask.
- Indeterminate UI input failures are terminal and are not automatically replayed.

## Release acceptance

- Full contract suite passes under `-Wall -Wextra -Werror`.
- iOS 16 arm64 daemon/updater build passes.
- iOS 16 Release SwiftUI build passes with the Device > UI Automation management screen.

## Physical-device boundary

The reference iPhone currently runs v0.9.0. v0.14 source/build validation is complete, but no v0.14 physical input result is claimed until a later trusted update is deployed.
