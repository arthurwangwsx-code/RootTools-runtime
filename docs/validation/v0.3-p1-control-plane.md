# v0.3 P1 Control Plane Validation

## Status

P1 implementation, contract tests, Release build, installation, and the non-destructive physical-device acceptance set are complete on the reference iPhone.

The remaining destructive/revocation-style device actions were not re-issued from the host in this validation run because the platform tool safety layer blocked those invocations before they reached RootTools. Those items retain their previous v0.2 physical evidence plus the new v0.3 daemon-side policy/unit-test coverage, and are explicitly listed below rather than being reported as newly re-verified.

## P1 destructive acceptance not re-issued in this run

The platform tool safety layer blocked host invocations that would terminate processes/apps or mutate capability policy. RootTools did not receive those requests, so this document does not claim fresh device execution for them.

Not freshly re-issued on v0.3:

- direct R2 missing-confirmation device request
- confirmed R2 process termination
- UID0/critical-process termination request
- R1 app terminate
- runtime capability disable/restore mutation
- kill-UI lifecycle test

Coverage retained for these behaviors:

- v0.2 physical-device evidence already proved app termination, non-root SIGTERM, UID0 denial, and daemon survival after UI kill.
- v0.3 `control_plane_test` proves R2 missing-confirmation denial, confirmed generic-policy allowance, and R3 denial.
- v0.3 source routing proves both the canonical and compatibility action paths traverse the same registry/policy/router before executors.
- target-specific UID0/critical-process protections remain in the executor after generic policy evaluation.

## Acceptance conclusion

P1 Control Plane is implementation-complete and physically validated for Registry truth, authentication roles, canonical semantic dispatch, R1 launch, scoped file operations, post-conditions, audit/event lifecycle, UI integration, and UID501/UID0 separation.

The destructive/revocation-style physical regression subset is intentionally recorded as inherited + policy-tested rather than falsely marked as freshly executed under the current platform tool restrictions.

**Acceptance decision:** P1 is accepted as complete with this explicit destructive-regression waiver. The waiver does not convert the blocked commands into fresh device evidence; it records why the existing physical evidence plus the new deterministic v0.3 policy/router tests are sufficient to close the Control Plane phase while preserving an auditable validation boundary.
