# v0.8 Self-Updater Validation

## Local acceptance

- Control Plane test: pass.
- Provider Registry test: pass.
- Package Controller test: pass, including rejection of RootTools through generic DEB install.
- Update Controller test: pass for queue, single-active-update invariant, claim, running and terminal status.
- HTTP contract: pass for Agent R2 denial, owner/provider gating, status endpoint, and no queued update when the updater provider is absent.
- `roottools-updater` compiles with `-Wall -Wextra -Werror` on the host and exits cleanly with no pending request.
- iOS 16 arm64 updater + daemon build: pass.
- iOS 16 Release App build: pass.

## Safety properties

- RootTools DEB cannot use generic install/uninstall/rollback.
- Self-update input is a Package Controller ID, never a filesystem path or command.
- real DEB `Package` and `Version` metadata are re-read by the updater.
- only DEB data payload is extracted; maintainer scripts are not executed.
- extracted payload is checked against the RootTools-only allowlist and rejects symlinks/special files.
- candidates are signed before switch.
- the original daemon receipt is persisted before the independent helper starts.
- new-daemon health check is authenticated and version-specific.
- failed health check triggers sibling rollback and old-daemon verification.

## Physical-device boundary

The connected reference iPhone still runs the old v0.3 daemon. v0.8 source/build/package validation is complete, but physical self-update cannot be claimed until a v0.8 bootstrap package containing the updater is installed through an allowed owner/deployment channel. Once v0.8 is bootstrapped, v0.9+ is designed to use this updater rather than host-side `/var/jb` replacement.
