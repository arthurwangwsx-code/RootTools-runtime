# v0.15 Permission Model Validation

## Contract invariants

- `/v1/policy` reports the current Owner policy mode and enabled R0/R1/R2 counts.
- `device.policy.set-mode` is R2 and bound to `roottools.execd`.
- a remote Agent cannot self-confirm a policy-mode change.
- Restricted mode disables normal R1/R2 execution but preserves `device.policy.set-mode` as the recovery escape hatch.
- Standard mode enables the compiled non-R3 surface and keeps explicit R2 approval.
- Developer mode enables the compiled non-R3 surface and auto-approves R2 only for the authenticated Owner credential.
- Named principals remain subject to exact R0/R1 grants in every mode.
- R3 and `device.raw-shell` remain hard disabled in every mode.
- individual capability changes mark the policy as Custom.

## Automated acceptance

- `control_plane_test` covers Custom, Restricted and Developer persistence plus the hard R3 invariant.
- `provider_registry_test` covers policy capability bindings.
- HTTP contract covers Agent denial, Restricted execution denial, Developer activation and Owner-only R2 auto-approval when leaving Developer mode.
- the full RootTools contract suite remains green under `-Wall -Wextra -Werror`.

## Product acceptance

- Settings contains a Developer Mode quick control.
- Capabilities shows Restricted / Standard / Developer profiles and the layered permission model.
- Agents > Capability Grants supports a one-action full R0/R1 development grant set without delegating R2.
- Mac Device Service exposes `policy`, `policy-mode`, and `principal-grant-all` convenience commands.

## Physical-device boundary

The reference iPhone still runs v0.9.0. v0.15 source/build validation does not claim physical Developer Mode behavior until the trusted updater/bootstrap path deploys a later build.
