# RootTools iOS v0.2 — Physical Device Validation

Date: 2026-08-23

Device under test:

- Model: iPhone14,3 (iPhone 13 Pro Max)
- iOS: 16.3.1 / build 20D67
- Jailbreak: Dopamine rootless
- App bundle: `com.arthur.roottools.ios`
- Daemon: `roottools-execd` v0.2.0

## Result

The v0.2 controlled-action milestone passed its physical-device acceptance criteria, except full reboot/re-jailbreak persistence, which is intentionally a separate milestone.

### Build and install

- Release build succeeded for `arm64-apple-ios16.0`.
- App installed under `/var/jb/Applications/RootTools.app`.
- App process runs as mobile UID 501.
- launchd daemon runs as UID 0 and remains independent of the UI process.

### Authentication and capability boundary

- Request without `X-RootTools-Token`: HTTP 401.
- Correct token: HTTP 200.
- Header-name matching was corrected to be HTTP case-insensitive after a real-client validation exposed the issue.
- R3 device-critical operations are not exposed.
- Arbitrary privileged shell is not exposed.
- Static source check found no `system()`/`popen()` path in the daemon.

### Application control

- `app.launch` successfully launched `com.apple.Preferences` and the process appeared as UID 501.
- `app.terminate` successfully terminated it and postcondition inspection confirmed the process disappeared.
- Each action returned an audit receipt.

### Process control

- `process.terminate` successfully sent SIGTERM to a disposable UID 501 Settings process on the final installed package.
- The same action was denied for the UID 0 RootTools daemon.
- The same action was denied for another UID 0 system process.
- The root daemon remained alive after denied attempts.

### Restricted file access

- UTF-8 write/read round-trip passed in the mobile scope.
- UTF-8 write/read round-trip passed in the jailbreak bootstrap scope.
- `../` traversal was rejected.
- An undeclared `system` scope was rejected.
- A malicious symlink inside the allowed directory was refused by `O_NOFOLLOW`; independent inspection confirmed the external target was not created.

### Audit

- Successful and denied typed actions both received `auditId` values.
- `/v1/audit` contained the matching success/denial records.
- Malformed requests remain HTTP 4xx and do not masquerade as semantic action receipts.

### UI and lifecycle

- Accessibility inspection confirmed `ROOT ONLINE`, `UID 0`, `v0.2.0`, `Capabilities`, `Audit Log`, and `Controlled Actions` on the dashboard.
- ZXTouch navigation successfully entered the Controlled Actions page.
- Accessibility inspection confirmed the App Launch/Terminate controls, R2 SIGTERM control, restricted file Read/Write controls, and policy text that R3/raw shell are unavailable.
- Killing the RootTools UI removed only the UID 501 app process; the daemon PID remained unchanged and continued serving authenticated API requests.
- Relaunching the UI reconnected successfully and again showed `ROOT ONLINE` with daemon v0.2.0.

## Not covered by this milestone

- Full device reboot followed by jailbreak restoration and automatic daemon recovery.
- R3 operations such as reboot, filesystem remounting, bootstrap mutation, or unrestricted system configuration.
- General cross-app arbitrary filesystem writes.
- Arbitrary root shell execution from the UI or an Agent.
