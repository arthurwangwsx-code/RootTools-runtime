# v0.9.1 Physical Hardening

## Purpose

v0.9.1 addresses two issues discovered only after the first successful v0.9 physical bootstrap: live TCC WAL access through SQLite and the rootless bootstrap `PATH` inherited by launchd services.

## Implemented fixes

- TCC reader first attempts the live database, then creates a POSIX-read-only snapshot of `TCC.db`, `TCC.db-wal`, and `TCC.db-shm` inside the RootTools private directory and opens only that disposable copy with `PRAGMA query_only=ON`.
- `ROOTTOOLS_TCC_FORCE_SNAPSHOT=1` and `ROOTTOOLS_TCC_SNAPSHOT_DIR` make the fallback deterministic in HTTP contract tests.
- `roottools-execd` and `roottools-updater` initialize a rootless-aware `PATH` before any fixed provider subprocess is spawned.
- daemon version and release package move to `0.9.1` / `0.9.1-1`.

## Deployment status

The physical device remains intentionally on the known-good v0.9.0 bootstrap while v0.9.1 is prepared. The first v0.9.0 self-update request safely failed during DEB metadata preflight because the old updater inherited a non-rootless `PATH`; no filesystem swap occurred. Do not claim v0.9.1 physical acceptance until the updated updater itself is bootstrapped or another approved migration path is available.
