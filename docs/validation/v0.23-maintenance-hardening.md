# v0.23 Repository and Credential Maintenance Hardening

Date: 2026-08-30

## Scope

This increment establishes one active iOS Runtime source and makes local credential handling fail closed. It does not add a new device capability or widen privileged authority.

The canonical iOS source and release repository is `arthurwangwsx-code/RootTools-runtime`. The historical `mobile-ios/RootTools` checkout is a recovery snapshot whose `origin` belongs to a different Android history and has no iOS development or release authority.

## Implemented controls

- Owner and Agent token files are created under `umask 077` and normalized to mode `0600` before use.
- Credential loading rejects symbolic links, non-regular files, malformed values and extra file content.
- The local release workflow requires the canonical GitHub repository, the `main` branch and an `origin/main` upstream before authentication, build, tag or push steps.
- `VERSION` is the single source for Debian package, daemon, App and verifier versions; packaging fails closed on mismatches or stale build stamps.
- DEB tar/gzip/ar timestamps are deterministic from `SOURCE_DATE_EPOCH` (default Git commit time), and package tests require repeated archives to be byte-identical.
- A three-phase Remote Access qualification tool creates only temporary least-privilege Host Principals, enforces an off-USB phase and records secret-free request/audit evidence for stop/expiry/revoke closure.
- Bash tests cover credential creation, legacy-permission normalization, malformed content, symbolic-link rejection, zsh sourcing compatibility and repository-boundary rejection.
- Repository ownership, credential migration and legacy-retirement gates are documented under `docs/maintenance/`.
