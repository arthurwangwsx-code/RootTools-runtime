## Physical-device boundary

The reference iPhone was bootstrapped successfully to daemon `0.9.0` on iOS 16.3.1 / iPhone14,3.

Verified on device:

- daemon is UID 0 and reports 47 typed capabilities;
- RootTools App launches through `ui.springboard`, passes the process post-condition, and remains running;
- Provider Plane reports Dopamine, Procursus, TrollStore, Sileo, Frida, ElleKit, OpenSSH, SpringBoard, ZXTouch, TCC, Darwin, daemon, and updater providers available;
- Frida semantic observation reports package `re.frida.server` 17.17.0, UID 0 server PID, port reachability, and no arbitrary script/attach exposure;
- ElleKit semantic observation reports package 1.2 and fixed runtime component availability with no raw hook/injection exposure;
- lock/display state and lock-aware automation report unlocked/visible with headless and UI execution ready;
- independent updater provider is installed and the R2 self-update scheduling action persists a durable request successfully.

Two physical findings remain as v0.9.1 hardening work:

1. Live TCC SQLite opening returns 503 even though UID 0 can read `TCC.db`, WAL, and SHM with POSIX I/O. v0.9.1 adds a read-only private snapshot fallback and a forced-snapshot HTTP contract test.
2. The launchd daemon/updater environment does not include the rootless bootstrap paths. `dpkg-deb` therefore cannot locate its `tar` subprocess, causing automatic DEB metadata inspection and the first self-update preflight to fail safely before any swap. v0.9.1 initializes `PATH` with `/var/jb/bin:/var/jb/usr/bin:/var/jb/sbin:/var/jb/usr/sbin` plus system paths.

The failed self-update left the installed v0.9.0 daemon and App healthy; no partial swap occurred.
