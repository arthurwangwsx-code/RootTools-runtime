# v0.19 Remote Worker Validation

## Product invariant

Remote Worker Mode keeps a personally owned jailbroken iPhone useful as a long-running automation node without turning availability into an excuse to ignore battery, thermal, passcode or permission policy.

The stable surface is:

- `device.remote-worker.observe` — R0 read-only state;
- `device.remote-worker.configure` — R2 Owner configuration;
- persisted bounded worker policy;
- low-brightness target managed by the local RootTools UI;
- daemon-owned idle-display assertion;
- battery percentage, temperature, power, cycle and health observations when available;
- thermal pause/resume hysteresis;
- UI Task Runtime gating while thermally paused;
- optional charge-guard policy that remains unavailable unless a reversible device path is explicitly verified.

## Safety acceptance

- Remote principals cannot self-confirm `device.remote-worker.configure`.
- Developer Mode does not change the hard R3/raw-shell boundary.
- RootTools never bypasses the device passcode.
- A configured thermal pause releases the RootTools-owned display assertion and blocks queued UI execution.
- Cooling below the resume threshold reacquires the assertion and re-allows UI work.
- Missing battery-temperature telemetry while Worker Mode is enabled is treated as a fail-safe thermal pause, not as `0°C`.
- Disabling Worker Mode releases the display assertion and any RootTools-owned reversible charge inhibit.
- Charge-control mutation fails closed on devices where a reversible charging helper has not been verified.

## Automated acceptance

`remote_worker_controller_test` covers:

- default persisted policy;
- assertion acquire/release;
- battery/power/health projection;
- charge-window hysteresis fixture;
- thermal pause and resume;
- missing-temperature fail-safe behavior;
- shutdown cleanup;
- JSON contract fields.

The HTTP contract covers R0 observation, R2 owner-only configuration and integration with the canonical Command Gateway. Provider tests prove the two semantic capabilities remain bound to `roottools.execd` rather than a caller-controlled executable.

## Physical-device boundary

The reference physical iPhone still runs RootTools daemon v0.9.0. v0.19 source/build validation does not claim physical Remote Worker behavior until the trusted updater migration is completed and `/v1/status` reports v0.19.0 or a later consolidated stable daemon on-device.
