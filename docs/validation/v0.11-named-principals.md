# v0.11 Named Principals Validation

## Implemented

- SQLite-backed named principal store;
- kinds: host/app/skill/automation;
- daemon-generated 48-character credentials;
- only SHA-256 credential hashes are persisted;
- Owner-only principal catalog;
- R2 Owner create/revoke capabilities;
- named-principal authentication through the Command Gateway;
- authenticated principal ID becomes receipt/audit caller identity;
- RootTools Agents UI can create/list/revoke named principals;
- plaintext credential is shown only after creation;
- legacy Agent credential remains available as a migration surface.

## Local acceptance

`principal_store_test` verifies:

- create and authenticate;
- wrong credential rejection;
- duplicate principal ID rejection;
- catalog does not contain plaintext token;
- revocation invalidates authentication;
- revoked state persists in catalog.

HTTP contract verifies:

- Agent cannot self-confirm principal creation;
- Owner creates a named host principal;
- Agent cannot read the owner-only principal catalog;
- newly issued credential authenticates as role `agent` with caller `principal:host:test-mac`;
- an R1 file write receipt carries that exact authenticated caller;
- Owner revocation immediately makes the credential return HTTP 401.

Existing Control Plane, Provider, Package, Updater, Runtime and Package Builder tests remain green.

## Not yet claimed

- per-principal capability allowlists;
- resource-level grants;
- credential expiry/rotation policy;
- pairing QR/deep-link UX;
- network relay/mTLS identity;
- physical-device v0.11 deployment.

These are subsequent trust-plane increments, not implicit properties of the v0.11 principal credential.
