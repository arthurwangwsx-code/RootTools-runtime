# RootTools iOS v0.2 — Controlled Actions

## Goal

Turn the v0.1 read-only jailbreak dashboard into a reusable privileged device control plane without turning the app or a future Agent into an unrestricted root shell.

The execution chain is fixed:

`SwiftUI -> DaemonClient -> authenticated loopback API -> typed daemon handler -> fixed Darwin API / fixed executable -> audit receipt`

No UI or Agent request can provide a shell program, shell flags, or a filesystem path outside the daemon's declared capability schema.

## Capability matrix

| Capability | Risk | Implementation | Guardrail |
| --- | --- | --- | --- |
| status/runtime/apps/processes/files/network/diagnostics | R0 | native Darwin APIs | read-only |
| capabilities/audit | R0 | daemon-owned metadata/log | read-only |
| file.read | R0 | `open/read` | two fixed RootTools directories, `O_NOFOLLOW`, 32 KiB cap |
| app.launch | R1 | fixed `/var/jb/usr/bin/uiopen` | validated bundle ID, no shell |
| app.terminate | R1 | `uicache -i` + fixed `killall -TERM` | validated bundle ID, critical executable denylist |
| file.write | R1 | `open/write/fsync` | fixed directories, safe filename, `O_NOFOLLOW`, 16 KiB cap |
| process.terminate | R2 | `kill(pid, SIGTERM)` | explicit UI confirmation; PID > 100; UID 0 and critical process denylist |
| device-critical operations | R3 | not implemented | unavailable |
| arbitrary privileged shell | N/A | not implemented | unavailable |

## Action receipt contract

Syntactically valid privileged actions always return a receipt, including policy denials and runtime failures:

```json
{
  "ok": false,
  "action": "process.terminate",
  "message": "Denied: root or critical process",
  "auditId": "..."
}
```

HTTP 4xx is reserved for malformed/unauthenticated requests. This ensures every attempted semantic action that reached policy evaluation can be correlated with the append-only audit log.

## Physical-device acceptance criteria

1. Release build succeeds with iOS 16.0 deployment target.
2. App installs to `/var/jb/Applications/RootTools.app` and launches as mobile UID 501.
3. `roottools-execd` runs as UID 0 under launchd and reports daemon version 0.2.0.
4. Missing token returns HTTP 401; correct token reaches typed endpoints.
5. `app.launch` launches a harmless system app by bundle ID; `app.terminate` terminates that same app and records receipts.
6. `file.write` + `file.read` round-trip exact UTF-8 content in both allowed scopes.
7. Traversal/invalid filenames are rejected and cannot write outside the two allowed directories.
8. `process.terminate` rejects the root daemon itself and another UID 0 target.
9. A disposable non-root process/app can be terminated with SIGTERM, proving the R2 success path without touching critical services.
10. `/v1/audit` contains the resulting audit IDs and success/denial outcomes.
11. Killing the UI does not kill the daemon; relaunch reconnects to the same control plane.
12. Accessibility inspection confirms the iOS UI exposes Controlled Actions, Capabilities, Audit Log, and the R3/raw-shell policy text.

Full reboot/re-jailbreak persistence is a separate milestone and is not implied by this acceptance test.
